# Content, research and media system

## Editorial workflow
Research → collect official/credible source evidence → cross-check claims and platform/version → draft original wording → classify spoilers → review permissions → founder approves publication → schedule recheck. Never fabricate content or treat AI output as evidence. Keep private source notes out of public builds. Official game developer/platform listings first; established guide publications and attributed creator footage next; community reports are leads, not established facts. Do not confuse GTA V or other games with GTA VI. Verify the official platform list and any current game information at the time of publication. If web access is absent, mark research blocked, and build/test with clearly isolated fixtures. Do not publish fixtures. Record source URL, publisher, title, check date, exact claim supported and conflicts. No wholesale copying, scraped proprietary maps or downloaded creator videos. Use official embeds only when allowed; click-to-load without third-party network requests before consent/interaction where feasible. External links validated; no raw HTML from untrusted content.

Verification states: official_confirmed, independently_verified, community_reported, unverified, outdated_or_patched. Publication states are separate: draft, review, approved, retired. Release default allows only approved, adequately verified claims. Founder gameplay evidence adds a distinct flag and date, never inferred from a screenshot alone; report which part was tested, on which platform and game version if known. Corrections should preserve stable IDs and update revision logs. Do not delete completed player objectives merely because a guide text changes; handle retired entries explicitly.

## Recommended schema (adapt with validation)
Use typed data and schemas; version changes. Game: id, slug, title, supportedPlatformIds, theme, officialSources, lastVerifiedAt, availabilityStatus. Platform: id, label, family, achievementSystem. Objective: id (immutable, namespaced by game), gameId, platformIds (or explicitly shared), kind (official achievement / trophy / in-game completion / optional challenge), safeTitle, safeSummary, protectedDetails, spoilerLevel, unlock/prerequisite IDs, storyGate (nullable), missable (true/false/unknown), category, sourceIds, verificationStatus, checkedAt, publicationStatus, revision. Item or guide: id, gameId, slug, category, safeTitle, safeSummary, spoilerLevel, protectedDetails, platformIds, mode, version, sourceIds, verificationStatus, checkedAt, publicationStatus, revision, mediaIds, videoIds, relatedObjectiveIds; optional rarity basis, region, coordinates, spawn conditions, acquisition, ownership, payout and timeframe only with evidence. Source: id, url, publisher, title, verifiedAt, supportedClaim, evidenceNotes (private if necessary). Media: id, gameId, guideIds, path, sourceType, sourceUrl, creator, rightsStatus, rightsNotes, altTextSafe, protectedCaption, spoilerLevel, capturePlatform, capturedAt, gameVersion, founderVerifiedAt, publicationStatus, width, height, variants. Video: id, verified URL and provider ID, creator, safe title, protected title, timestamps, guideIds, spoilerLevel, checkedAt, embedAllowed. Map: id, gameId, coordinateSystem, markerType, coordinates, safeLabel, spoilerLevel, relatedObjectiveIds, sourceIds; licensed map asset separately. Progress: schemaVersion, per game/per platform context, completed objective IDs, bookmarks, notes, updatedAt, spoiler preference; avoid sensitive data, handle malformed and older versions safely, export JSON and preview before import, preserve local data on failure.

## Media strategy
1. Initial development: research official Rockstar GTA VI media and other high-quality sources. Verify permissions for intended public/commercial use; availability to view or download does not mean licensed for reuse. Do not hotlink or scrape images as a substitute for permission. Use authorized assets or original licensed generic tropical placeholders clearly labeled illustrative if rights unclear. Keep an asset register and credit where required. No game imagery is bundled.
2. Founder gameplay: Xbox initially; support captures from all relevant platforms. Capture one in-game map/location view and one landmark/scene where useful. Store originals privately, optimized public derivatives separately, attach guide IDs, alt text, source, platform, capture date, spoiler and permission status. Review publisher policy even for self-captured gameplay, and remove account identifiers, private messages or sensitive details before publication. Do not imply a founder screenshot confirms every related claim.
3. Future: secure founder-only Content Studio with upload validation, size/type limits, authenticated authorization, previews, draft/review/publication, revisions and rollback. No unsecured admin page or frontend secrets. MVP uses a documented directory and structured records so Claude/founder can swap media without changing layout code. Recommend a simple naming convention `game-category-subject-platform-YYYYMMDD-01.ext` and keep stable media IDs separate from filenames. Preserve original brand asset; optimize derivatives with aspect ratio maintained.

## Spoiler discipline
Redact titles, summaries, alt text, tags, thumbnails, video titles, metadata, paths and search index entries by default. Protected text should not appear in initial visible content, accessible labels, autocomplete or social previews. Do not request protected image/video resources before explicit reveal where practical. Story gates are optional and only used if supported by verified content. Avoid false safety guarantees: third-party videos/external sites can expose spoilers, show neutral warning before departure. Test direct navigation, filters, reload, sharing and mode changes.
